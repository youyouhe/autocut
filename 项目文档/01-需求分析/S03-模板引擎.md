## 一、系统概述

### 1.1 系统定位

模板引擎（template_engine.py）是 AI 视频工作台"内容生产"分册的声明式生产能力核心。它以 **YAML 声明式视频模板**为输入，经**变量填充**与**Scene 处理器**分发，自动调用 VectCutAPI（S05）草稿编辑端点组装剪映草稿，并可（可选）直接触发无人值守渲染（S06），形成"模板 + 变量 → 草稿 →（可选）成片"的一条龙生产线。

模板引擎解决的业务问题：将"逐条调用 create_draft/add_video/add_text…等编辑 API"的手工编排，抽象为一份可版本化、可复用、可批量填充变量的 YAML 模板文件，使同一形态的视频（产品介绍、知识短视频、情感语录等）可按不同素材与文案参数化批量生产，无需用户具备剪辑操作能力。

### 1.2 业务范围

本系统覆盖以下能力域：

1. **模板定义与解析**：YAML 模板格式（name/description/canvas/scenes[]/render）的加载与结构校验（S03-001）；
2. **变量填充**：`{{var}}` 占位符在 str/dict/list 任意层级上的递归替换（S03-002）；
3. **Scene 场景处理器**：video/image/text/audio/subtitle 五种类型处理器的分发与组装（S03-003 ~ S03-007），以及 overlay 叠加层与时间游标控制（S03-008）；
4. **模板执行与交付**：组装 → 保存 → 可选渲染的执行流程（S03-009），内置模板库与模板 API（S03-010）。

### 1.3 用户角色

引用 `_metadata.md` 角色定义，S03 关联角色子集：

| 角色编码 | 角色名称 | 在本系统中的职责 |
|---------|---------|----------------|
| R01 | 视频创作者 | 通过 Web GUI / REST API（/api/templates、/api/templates/render）选择内置模板、提交变量并执行模板生产 |
| R03 | 脚本/程序调用方 | 通过命令行（template_engine.py list/render）或 REST API 将模板执行嵌入自动化批量生产流水线 |

### 1.4 系统边界

**本系统负责**：模板 YAML 的解析与校验、变量填充、Scene 分发与组装编排、时间游标管理、执行流程编排、内置模板库管理与模板 API。

**本系统不负责**（由下游系统承担）：

- 草稿文件的物理生成与落盘 —— 由 S05 草稿编辑服务（VectCutAPI，基于 pyJianYingDraft）承担；
- 渲染执行、多桌面调度、剪映 UI 驱动 —— 由 S06 无人值守渲染与 EXT-01 剪映专业版 5.9.0 承担；
- 素材上传与元数据感知 —— 由 S01/S02 承担（本系统只按 `{{变量}}` 接收已就位的素材路径）；
- 对话式按需编排 —— 由 S04 承担（S04 走 Function Calling 逐步调编辑工具，与本系统的模板批量生产互补）。

## 二、功能需求

### 2.1 模板定义与解析

#### S03-001 YAML 模板定义解析（canvas/scenes/render）

##### 一、功能综述

模板引擎采用声明式 YAML 作为视频模板的载体。一份模板由四部分组成：`name`/`description`（模板元信息）、`canvas`（画布分辨率）、`scenes[]`（有序场景列表，每个场景声明类型、素材/内容、起止时间、样式、位置、动画、转场、叠加层、轨道名等）与 `render`（渲染分辨率与帧率）。

本功能负责从 `templates/` 目录或用户指定路径加载 YAML 文件，解析为内存模板对象并执行结构校验（必需段齐全、type 枚举合法、时间参数合法等），为后续变量填充（S03-002）与场景组装（S03-003~008）提供统一的数据结构。模板格式是模板引擎全部 10 个功能点的公共数据契约。

> 数据类型遵循 `_metadata.md` 数据类型约定；本项目无关系型数据库，模板以 YAML 文件形态存储于文件系统。

##### 三、业务活动

1. **模板加载**：从 `templates/` 内置目录或命令行/API 指定路径读取 YAML 文件；
2. **结构解析**：解析 name/description/canvas/scenes/render 五段为内存模板对象；
3. **结构校验**：必需段齐全性、scenes 非空、type 枚举合法性、source/content 条件必填、时间参数（start<end、duration≥0）合法性校验；
4. **缺省值补全**：canvas 缺省 1080×1920、render 缺省沿用 canvas 与 30fps、start 缺省取当前游标、overlay 缺省 false；
5. **错误报告**：解析或校验失败时返回含文件名与错误位置的明确错误信息，终止本次模板执行。

#### S03-002 变量填充（{{var}} 递归替换）

##### 一、功能综述

模板中的占位符采用 `{{变量名}}` 语法，可出现在任意层级的字符串值中——包括 scenes[].source（素材路径）、scenes[].content（文案）、style 内的颜色值、甚至整个 style/position/animation 子对象。执行模板时，用户通过 `-v '{"k":"v"}'` 命令行参数或 API 的 `variables` 字段提交变量表。

本功能（`_fill`）对模板对象做**递归遍历替换**：对 str 类型做占位符替换，对 dict/list 类型深入其内部继续递归，使变量值既可以是标量（一个标题字符串），也可以是结构（一段字幕 items 列表、一个完整 style 对象）。变量填充是模板从"静态样板"变为"参数化生产线"的关键环节，直接支撑流程 B 的批量生产。

##### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-03-002 | 变量上下文（Variables） | variable_key | VARCHAR | 64 | Y | 与模板中 `{{key}}` 占位符名精确匹配 | 变量名，区分大小写 |
| BO-03-002 | 变量上下文（Variables） | variable_value | TEXT(JSON) | - | Y | 标量 str / dict / list 皆可 | dict/list 值支持整体替换结构化占位符 |
| BO-03-002 | 变量上下文（Variables） | fill_scope | VARCHAR | 10 | Y | 枚举：str / dict / list / 全模板 | 递归填充覆盖模板全部层级 |
| BO-03-002 | 变量上下文（Variables） | variables_payload | TEXT(JSON) | - | N | 命令行 -v JSON 串 / API variables 字段 | 整体变量表，可为空（模板无占位符时） |

##### 三、业务活动

1. **变量表接收**：从命令行 `-v` JSON 参数或 `/api/templates/render` 请求体 `variables` 字段接收变量表并解析；
2. **递归填充**：遍历模板对象，str 值执行 `{{var}}` 替换，dict/list 值递归下钻；
3. **未填充检测**：填充后扫描模板，检测仍残留 `{{...}}` 的位置；
4. **结果交付**：输出完全实例化的模板对象，交给 Scene 处理器执行（S03-003~008）。

##### 用例 U-03-002-01

| 项目 | 内容 |

**功能要求：**

| 类型 | 描述 |
|------|------|
| 基本功能 | 共计 4 个基本功能点：|
| | 1. 解析命令行 -v / API variables 的 JSON 变量表 |
| | 2. 递归替换 str/dict/list 中的 `{{var}}` 占位符 |
| | 3. 支持结构化变量值（dict/list）整体注入 |
| | 4. 填充后残留占位符检测与定位报错 |
| 辅助功能 | 空变量表且模板无占位符时直接透传模板（幂等） |
| 提示信息 | "变量 {{product_name}} 未提供：场景 2 content 字段" |

**处理逻辑：**
1. 解析变量表 JSON，校验为 dict 结构（key→value）；
2. 从模板根对象开始递归：str 值做占位符匹配替换；dict 对每个 value 递归；list 对每个元素递归；
3. 替换完成后全模板扫描 `{{`，发现残留即收集全部残留位置一次性报错；
4. 输出实例化模板对象。

**约束条件：**
1. 占位符语法为双花括号 `{{var}}`，变量名须与 variable_key 精确匹配（区分大小写）；
2. 变量表整体大小受请求体限制（JSON 文本，遵循元数据"长文本 TEXT"约定）；
3. 填充只做文本/结构替换，不做表达式运算（不支持 `{{a+b}}`）。

**信息处理要求：**

| 方向 | 内容 |

| 输入信息 | 变量表 JSON（BO-03-002，命令行 -v 或 API variables 字段） |
| 输出信息 | 实例化模板对象（BO-03-001 的填充后形态）；或残留占位符错误清单 |

**业务表单：** 变量表（BO-03-002）

### 2.2 Scene 场景处理器

> 公共机制：执行器按 scenes 顺序遍历，依据 type 将场景分发到 `_scene_video / _scene_image / _scene_text / _scene_audio / _scene_subtitle` 五个处理器；处理器将公共属性（BO-03-001 scenes[] 段）与本类型特有属性（各功能点业务对象）翻译为对应的 S05 编辑端点调用。

#### S03-003 video 场景处理器

##### 一、功能综述

video 场景是模板的主画面载体。`_scene_video` 处理器将场景中的视频素材（source，支持 `{{变量}}` 注入的素材路径）添加为剪映视频轨道，按 start/end/duration 计算入点出点，可选挂接转场（transition，如 slide_left）与具名轨道（track_name），并默认推进时间游标，使后续场景自动衔接在其后。

典型用法：产品介绍模板的"演示"环节引用 `{{demo_video}}` 变量，同一模板换一个变量值即可生产不同产品介绍视频；多段 video 场景顺序排列配合转场即构成正片主体。

| BO-03-003 | video 场景配置 | end | DECIMAL | (10,3) | C | 同上 | 与 duration 二选一 |

#### S03-008 overlay 叠加层与时间游标控制

##### 一、功能综述

模板引擎用**单一时间游标（cursor）**驱动顺序组装：每个非 overlay 场景落轨后把游标推进到自己的结束点，下一个场景缺省从新游标开始——这使模板作者无需手工累加时间即可实现"标题 3 秒 → 演示 15 秒 → 特点 5 秒"的顺序衔接。

`overlay: true` 是对游标机制的显式例外声明：叠加层场景（浮于视频上的标题文字、角标图、贯穿全片的字幕/BGM）**不推进游标**，仅按自身 start（或当前游标）+duration 落轨。本功能定义游标状态、推进规则与 overlay 裁决规则，是五种 Scene 处理器（S03-003~007）共同遵循的时间线内核。

##### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-03-008 | 时间游标与叠加层控制 | cursor | DECIMAL | (10,3) | Y | 遵循元数据"时间区间"约定（秒） | 当前主线时间游标，初始 0，随非 overlay 场景推进 |
| BO-03-008 | 时间游标与叠加层控制 | overlay | BOOL | 1 | Y | 遵循元数据"布尔"约定 | 场景级开关，缺省 false；true=不推进游标 |
| BO-03-008 | 时间游标与叠加层控制 | scene_start | DECIMAL | (10,3) | N | 同上 | 场景显式 start；缺省取执行时游标快照 |
| BO-03-008 | 时间游标与叠加层控制 | scene_end | DECIMAL | (10,3) | N | 同上 | scene_start + duration/end 推算 |
| BO-03-008 | 时间游标与叠加层控制 | track_name | VARCHAR | 32 | N | — | 叠加层建议落具名轨道，与主线轨道隔离 |

##### 三、业务活动

1. **游标初始化**：模板执行开始时 cursor=0；
2. **逐场景裁决**：每个场景执行前记录游标快照作为缺省 start；执行后按 overlay 标志决定 cursor 是否推进至 scene_end；
3. **叠加层落轨**：overlay=true 场景以快照/显式 start 落轨，游标回退为快照值；
4. **总时长形成**：全部场景执行完毕后 cursor 即模板成片主线总时长。

##### 四、用例描述

##### 用例 U-03-008-01

| 项目 | 内容 |
|------|------|

| 业务说明 | 混合场景模板（视频主线 + 浮层标题 + BGM）执行时，非 overlay 场景顺序推进游标实现自动衔接，overlay 场景浮于主线之上不占用主线时长，最终游标即成片总时长 |

| 使用范围 | R01 视频创作者、R03 脚本/程序调用方 |

### 2.3 模板执行与交付

#### S03-009 模板执行流程（组装→保存→可选渲染）

##### 一、功能综述

模板执行流程是模板引擎的编排主线：**加载 YAML → 填充变量 → create_draft → 遍历 scenes 调对应 add_* API → save_draft →（可选）render/draft/\<id\>**。它把前述功能点（解析 S03-001、填充 S03-002、五处理器 S03-003~007、游标 S03-008）串接为一次完整生产：输入一份模板+一组变量，输出一个已保存的剪映草稿（draft_id），并可在同一次调用中顺带提交渲染（命令行 `-r` / API `render:true`），直接得到成片。

"可选渲染"设计覆盖两类用法：仅组装（用户想先在剪映中人工微调草稿）与组装即渲染（流程 B 无人值守批量生产）。

##### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-03-009 | 模板执行结果 | draft_id | VARCHAR(UUID) | 36 | Y | 遵循元数据"草稿ID draft_id"约定 | S05-001 /create_draft 返回 |
| BO-03-009 | 模板执行结果 | draft_path | VARCHAR | 260 | Y | 遵循元数据"文件路径"约定 | save_draft 落盘的草稿文件夹（含 draft_content.json） |
| BO-03-009 | 模板执行结果 | status | VARCHAR | 10 | Y | 枚举：assembled / rendering / done / error | 组装完成 / 已提交渲染 / 渲染完成 / 失败 |
| BO-03-009 | 模板执行结果 | task_id | VARCHAR(Hex) | 8 | C | 遵循元数据"任务ID task_id"约定 | 选择渲染时由 S06 返回 |
| BO-03-009 | 模板执行结果 | error_message | TEXT | - | N | — | 失败阶段的错误信息（解析/填充/组装/保存/渲染） |

##### 三、业务活动

1. **组装编排**：依次执行模板加载→变量填充→创建草稿→按序分发 Scene 处理器→保存草稿；
2. **草稿落盘**：调 S05-002 /save_draft 生成草稿文件夹，取得可注入剪映的完整草稿；
3. **可选渲染提交**：组装成功且用户请求渲染时，调 S06 `/render/draft/<draft_id>` 提交渲染任务，取得 task_id；
4. **状态与错误上报**：任一环节失败即中止并将阶段化错误信息返回调用方；成功则返回 draft_id（及 task_id）。

#### S03-010 内置模板库与模板 API（list/render）

##### 一、功能综述

系统在 `templates/` 目录内置三套开箱即用的模板：`product_intro.yaml`（产品介绍：标题→演示→特点→CTA→BGM）、`knowledge_short.yaml`（知识短视频）、`emotional_quotes.yaml`（情感语录）。本功能提供两方面的能力：

1. **模板库管理**：枚举 templates/ 目录，输出可用模板清单（名称/描述/场景结构）；
2. **模板 API 与命令行**：`GET /api/templates` 列模板、`POST /api/templates/render`（请求体 `{template, variables, render?}`）执行模板；命令行 `python template_engine.py list` 与 `render -t <yaml> -v '<json>' -r` 提供等价的脚本入口。

模板库使非专业用户零成本起步（改变量即产片），模板 API 使 R01 经 Web GUI、R03 经脚本/HTTP 均可驱动模板生产。

##### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-03-010 | 内置模板条目 | file_name | VARCHAR | 64 | Y | templates/ 目录下 .yaml 文件名 | product_intro / knowledge_short / emotional_quotes 等 |
| BO-03-010 | 内置模板条目 | name | VARCHAR | 64 | Y | 引用 BO-03-001.name | 模板显示名 |
| BO-03-010 | 内置模板条目 | description | VARCHAR | 200 | N | 引用 BO-03-001.description | 模板用途说明 |
| BO-03-010 | 内置模板条目 | scene_count | INT | 4 | Y | 模板场景数 | 供列表展示结构概况 |
| BO-03-011 | 模板渲染请求 | template | VARCHAR | 64 | Y | 模板名或模板文件路径 | /api/templates/render 请求体字段 |
| BO-03-011 | 模板渲染请求 | variables | OBJECT(JSON) | - | N | 引用 BO-03-002 | 变量表，无占位符模板可省 |
| BO-03-011 | 模板渲染请求 | render | BOOL | 1 | N | 遵循元数据"布尔"约定 | 默认 false（仅组装）；true=组装后直接渲染 |

##### 三、业务活动

1. **模板枚举**：扫描 templates/ 目录全部 .yaml，逐个读取元信息（name/description/场景数）；
2. **模板清单发布**：经 `GET /api/templates` 或命令行 `list` 输出可用模板列表；
3. **模板执行受理**：接收 `/api/templates/render` 请求（template/variables/render）或命令行 `render -t -v -r`，交 S03-009 执行流程；
4. **结果返回**：将执行结果（draft_id / task_id / status / 轮询地址）返回调用方。
