## 2.2 渲染驱动闭环
### S06-006 草稿注入（inject_draft）
#### 一、功能综述
剪映无 openDraft/loadDraft API，让任意草稿上首页的唯一途径是文件系统注入：把源草稿
文件夹复制进剪映草稿根目录 DRAFT_ROOT，改写 draft_meta_info.json 的 draft_id（新
UUID）/draft_name/draft_fold_path/tm_draft_modified=now 及 draft_content.json 的 id。
剪映实时监视 DRAFT_ROOT，新文件夹约 2 秒内出现在首页；tm_draft_modified=now 使注入
草稿排首页第一，桌面模式直接点 card 即可打开、无需搜索（三大根因修复之一）。
#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-006 | 注入草稿 | source_fold_path | VARCHAR | 260 | Y | BO-06-001.draft_fold_path | 源草稿只读 |
| | | draft_id | VARCHAR(UUID) | 36 | Y | 注入时生成新 UUID | 与源草稿 id 解耦 |
| | | draft_name | VARCHAR | 32 | Y | rd&lt;毫秒时间戳&gt; | 纯英文数字，规避 IME/QString |
| | | draft_fold_path | VARCHAR | 260 | Y | DRAFT_ROOT/&lt;draft_name&gt; | 注入副本路径 |
| | | tm_draft_modified | BIGINT | 毫秒 | Y | 注入时刻 now | 排首页第一的关键 |
| | | draft_root | VARCHAR | 260 | Y | 剪映 com.lveditor.draft 目录 | EXT-01 文件系统 |
#### 三、业务活动
生成注入名 → 复制文件夹至 DRAFT_ROOT → 改写 draft_meta_info.json 四字段与
draft_content.json 的 id → 等待约 2 秒剪映首页识别。

### S06-007 真后台桌面隔离（CreateDesktopW + lpDesktop）
#### 一、功能综述
真后台是"无人值守"的基石：经 Win32 OpenDesktopW/CreateDesktopW 创建（或打开）独立
Windows 桌面（如 JYRender_0），以 CreateProcessW 的 STARTUPINFO.lpDesktop 指向该桌面
启动剪映，并以 STARTF_USESIZE 设 dwXSize/dwYSize=1280×720（与校准基准一致）。剪映
在该桌面即为前台窗口，focusWindow() 返回有效指针、合成事件可注入；Frida 从主桌面
Python 进程跨桌面 attach（by PID）。渲染结束仅 kill 自己启动的剪映 PID。
#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-007 | 渲染桌面会话 | desktop_name | VARCHAR | 32 | Y | BO-06-004（JYRender_0/1） | 默认 JYRender |
| | | desktop_handle | POINTER | - | Y | OpenDesktopW/CreateDesktopW 返回 | 已存在则打开复用 |
| | | jy_pid | INT | - | Y | CreateProcessW 返回 | 仅记录自己启动的 PID |
| | | lpDesktop | VARCHAR | 32 | Y | STARTUPINFO.lpDesktop=桌面名 | 剪映在该桌面启动 |
| | | window_size | INT | 4 | Y | 1280×720（STARTF_USESIZE） | 与 calib 基准一致 |
#### 三、业务活动
打开/创建独立桌面 → 组装 STARTUPINFO（lpDesktop + STARTF_USESIZE 1280×720）→
CreateProcessW 启动剪映 → 等待进入首页 → 渲染完成后按 jy_pid kill 剪映。

### S06-008 渲染流程闭环（card→export→confirm→done→close，含 4/5 次重试）
#### 一、功能综述
渲染闭环是驱动核心：注入完成后，桌面模式点首页第一卡片（card）进入编辑器，经 wait_editor_ready（showCount 增加且稳定 1.5s，最多 5 次重试）确认就绪；随后进入导出循环（最多 4 次）：记录 base_show → click(export) → 等导出 modal 出现 → clickmodal(confirm)（confirm 位于 modal，须用 lastShownWin）→ wait_render_done(20s) 成功则跳出。完成后 clickmodal(close_done) 关完成弹窗、click(close_editor) 返回首页，最后执行草稿清理（S06-010）。前台模式以 search_btn→search_box→输入草稿名→result_card 检索代替首页直点。重试机制针对两大时序不稳：编辑器打开（5 次）与导出 modal/confirm（4 次，每次重新点导出刷新 modal）。
#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-008 | 渲染闭环上下文 | stage | VARCHAR | 16 | Y | 阶段枚举（见状态流转） | 当前闭环阶段 |
| | | desktop_mode | 布尔 | 1 | Y | --desktop 时 true | 决定检索方式 |
| | | editor_ready_retry | INT | 1 | Y | 上限 5 次 | wait_editor_ready 重试计数 |
| | | export_retry | INT | 1 | Y | 上限 4 次 | 导出循环重试计数 |
| | | base_show_count | INT | 4 | Y | get_shown_count() 基线 | 检测 modal 新窗口 |
| | | dev | POINTER | - | Y | primaryPointingDevice() | 合成事件必要参数 |

> 前台模式附加检索词 search_name（=草稿名）；点击坐标取自 BO-06-011 校准坐标表。
#### 三、业务活动
获取 dev → 打开编辑器（桌面点 card / 前台搜索）→ wait_editor_ready → 导出循环
（export→modal→confirm→完成检测）→ 关完成弹窗 → 关编辑器回首页 → 触发 S06-010 清理。

| 项目 | 内容 |
|------|------|

| 使用范围 | R04 系统运维/开发者；任务提交方（R01/R02/R03）间接受益 |
| 先决条件 | 注入完成且剪映已识别（S06-006）；桌面会话已建立（S06-007）；calib 8 坐标齐备（S06-011） |
**功能要求：**

| 类型 | 描述 |
|------|------|
| 基本功能 | 共计 6 个基本功能点：|
| | 1. 程序化获取 dev（primaryPointingDevice）；2. 打开编辑器（桌面点 card / 前台搜索）+ wait_editor_ready（5 次重试） |
| | 3. 导出循环（4 次重试：export→等 modal→clickmodal(confirm)）；4. wait_render_done(draft_name, 20s) 完成判定（见 S06-009） |
| | 5. clickmodal(close_done) + click(close_editor) 关闭返回；6. 触发草稿清理（S06-010） |
| 辅助功能 | 前台模式 resize_jianying() 调至 PRESET 1280×720；每轮导出重取 base_show |
| 提示信息 | 各阶段重试与失败原因写入驱动日志 |

**处理逻辑：**
1. 注入后获取 dev，按模式打开编辑器并等待就绪（≤5 次）；
2. 导出循环 ≤4 次：base_show → click(export) → 等 modal → clickmodal(confirm) → wait_render_done(20s)，成功 break；
3. 关闭完成弹窗与编辑器返回首页，执行清理并回写结果给 M01。

**状态流转：**

| 当前状态 | 事件 | 目标状态 | 前置校验 | 后置动作 |
|---------|------|---------|---------|---------|
| 注入完成 | 点 card（桌面）/ result_card（前台）且 editor_ready 通过（≤5 次重试） | 编辑器就绪 | showCount 增加且稳定 1.5s | 取 base_show，进入导出 |
| 注入完成 | editor_ready 重试 5 次耗尽 | 失败退出 | — | 记录原因，kill 剪映，任务 error |
| 编辑器就绪 | click(export) 且导出 modal 出现 | 导出确认 | 窗口显示数 &gt; base_show | — |
| 导出确认 | clickmodal(confirm) 且 wait_render_done 成功（20s 内） | 渲染完成 | mp4 满足完成判据（S06-009） | break 导出循环 |
| 导出确认 | confirm 未触发渲染 / 20s 未完成 | 编辑器就绪（重试） | export_retry &lt; 4 | 重取 base_show，重点 export 刷 modal |
| 编辑器就绪 | 导出重试 4 次耗尽 | 失败退出 | — | 记录原因，kill 剪映，任务 error |
| 渲染完成 | clickmodal(close_done) | 完成弹窗已关 | 完成弹窗为最近 modal | — |
| 完成弹窗已关 | click(close_editor) | 已回首页 | — | 触发 S06-010 清理注入草稿 |
| 已回首页 | 清理完成 | 闭环结束 | root_meta 同步成功 | 释放桌面，回写任务 done |

**约束条件：**
1. confirm 与 close_done 必须用 clickmodal（modal 是独立 QWindow，经 focusWindow 会点空）；
2. 每轮导出前必须重取 base_show，modal 判定只认相对基线的增量；
3. 任何失败路径都必须 kill 自己启动的剪映并释放桌面，避免桌面泄漏。

### S06-010 草稿清理与 root_meta 同步

### S06-011 坐标校准（calibrate）
#### 一、功能综述
UI 自动化的全部点击依赖 calib.json 的 local 坐标（相对窗口原点，随窗口移动稳定，global = origin + local）。校准以 1280×720 窗口为基准，引导运维依次点击关键按钮记录坐标，共 8 个：card/export/confirm/close_done/close_editor/search_btn/search_box/result_card，其中 confirm 与 close_done 位于 modal 窗口，运行时须经 clickmodal 点击，其余经 click（focusWindow）。分辨率/DPI 或窗口布局变化必须重校准。
#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-011 | 校准坐标表 | coord_key | VARCHAR | 16 | Y | card/export/confirm/close_done/close_editor/search_btn/search_box/result_card | 8 键枚举 |
| | | lx | INT | 4 | Y | 1280×720 local 坐标系 | 相对窗口原点 X |
| | | ly | INT | 4 | Y | 同上 | 相对窗口原点 Y |
| | | click_type | VARCHAR | 10 | Y | click / clickmodal | confirm、close_done 为 clickmodal |

> 当前基准值（1280×720 local）：card(275,336)、export(1136,18)、confirm(509,635)、
> close_done(580,396)、close_editor(1263,21)、search_btn(799,260)、search_box(660,262)、
> result_card(277,342)。
#### 三、业务活动
启动校准（render_driver.py calibrate）→ 依次引导点击关键按钮 → 记录 local 坐标 →
写入 calib.json → 渲染闭环读取使用。
