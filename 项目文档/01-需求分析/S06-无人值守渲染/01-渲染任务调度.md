### S06-001 渲染任务提交（zip 直传 /render）

#### 一、功能综述

zip 直传是全链路最快的出片方式（手册 §17 流程 D）：调用方将完整剪映草稿文件夹压缩为
zip 上传，服务端解包后直接进入渲染队列，异步返回 task_id 与轮询地址。它面向脚本化
批量生产（R03），Web GUI 渲染面板（R01）与 MCP 渲染工具（R02）复用同一入口。
渲染耗时数十秒且不可同步等待，必须任务化接入：HTTP 即时返回、后台池排队执行。

#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-002 | zip 直传渲染包 | zip_file | FILE(zip) | - | Y | multipart 字段 draft | 草稿文件夹压缩包 |
| | | draft_name | VARCHAR | 32 | N | 调用方指定 | 缺省生成 rd&lt;毫秒时间戳&gt; |
| | | has_draft_content | 布尔 | 1 | Y | 解包校验 | zip 内必须含 draft_content.json |
| BO-06-001 | 渲染任务 | task_id | VARCHAR(Hex) | 8 | Y | uuid hex 前 8 位 | 主键 |
| | | draft_name | VARCHAR | 32 | Y | BO-06-002 | 渲染与产物定位依据 |

#### 三、业务活动

接收 multipart 上传 → 校验 zip 结构（必须含 draft_content.json）→ 解包落盘 →
创建渲染任务（status=queued）→ 入渲染队列 → 即时返回 task_id 与 poll 地址。

### S06-002 按草稿 ID 渲染（/render/draft/&lt;draft_id&gt;）

### S06-003 任务生命周期管理（queued/rendering/done/error + 产物登记）

#### 一、功能综述

所有渲染任务（zip 直传与 draft_id 两种来源）共用同一生命周期 queued → rendering →
done / error，以 task_id（uuid hex 前 8 位）为主键贯穿。任务状态存于内存字典
tasks[task_id] 并以 TASK_LOCK 保护；done 后登记渲染产物（mp4_path / mp4_name /
duration）。本功能是渲染域的状态机中枢，S07-007 渲染面板、S04-004 render_status
对话工具均读取其状态。

#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-001 | 渲染任务 | task_id | VARCHAR(Hex) | 8 | Y | uuid hex 前 8 位 | 主键 |
| | | task_type | VARCHAR | 10 | Y | 枚举 zip / draft_id | |
| | | draft_id | VARCHAR(UUID) | 36 | N | S05-001 | draft_id 来源时必填 |
| | | draft_name | VARCHAR | 32 | Y | 注入草稿名 rd&lt;ms&gt; | 产物查找键 |
| | | draft_fold_path | VARCHAR | 260 | Y | 源草稿/解包路径 | |
| | | status | VARCHAR | 10 | Y | 枚举 queued/rendering/done/error | 状态机字段 |
| | | desktop_name | VARCHAR | 32 | N | BO-06-004 | rendering 占用的桌面 |
| | | error | TEXT | - | N | 失败原因 | |
| | | mp4_path | VARCHAR | 260 | N | BO-06-005 | done 后登记 |
| | | mp4_name | VARCHAR | 255 | N | 产物文件名 | |
| | | duration | DECIMAL | (10,3) | N | EXT-05 ffprobe | 秒 |
| | | created_at | BIGINT | 毫秒 | Y | 入队时间 | |
| | | updated_at | BIGINT | 毫秒 | Y | 最近状态变更 | |
| BO-06-005 | 渲染产物 | task_id | VARCHAR(Hex) | 8 | Y | BO-06-001 | 关联任务 |
| | | mp4_name | VARCHAR | 255 | Y | &lt;draft_name&gt;*.mp4 | |
| | | mp4_path | VARCHAR | 260 | Y | C:\Users\Administrator\Videos\ | 渲染输出目录 |
| | | size_bytes | INT | - | Y | &gt;100KB 且稳定 2 次才登记 | 见 S06-009 |
| | | duration | DECIMAL | (10,3) | N | ffprobe 提取 | |

#### 三、业务活动

任务创建（queued）→ worker 领取并占用桌面（rendering）→ 驱动闭环执行 → 完成检测
成功登记产物（done）或异常记录原因（error）→ 释放桌面。全程状态读写加锁。

| 类型 | 描述 |

1. 任务入队时置 queued、created_at；

**状态流转：**

| 当前状态 | 事件 | 目标状态 | 前置校验 | 后置动作 |
|---------|------|---------|---------|---------|
| （无） | zip 直传 / draft_id 提交校验通过 | queued | zip 含 draft_content.json；或草稿文件夹存在 | 建 tasks[task_id]，入 RENDER_QUEUE |

| queued | worker 领取且 acquire_desktop 成功 | rendering | 桌面池有空闲桌面（等待 ≤600s） | 记 desktop_name，启动 render-draft 子进程 |
| rendering | 完成检测通过且产物匹配成功 | done | mp4 &gt;100KB 且大小稳定 2 次 | 登记 mp4_path/mp4_name/duration，释放桌面 |

| done / error | —（终态） | — | — | 供 /render/status、/render/list 查询 |

**约束条件：**
1. done/error 为终态，不允许回退或重复流转；
2. 状态流转与产物登记必须原子（同锁内完成）；

| 功能点 | 使用人员 |
|--------|---------|

### S06-004 多桌面渲染池（2 桌面互斥 + 阻塞队列 worker）

#### 一、功能综述

渲染池以两个独立 Windows 桌面（JYRender_0 / JYRender_1）实现 2 路渲染并行：
desktop_pool 记录各桌面 busy 状态，RENDER_QUEUE 为阻塞队列，N 个 daemon 线程
worker 各自取任务 → acquire_desktop 申请空闲桌面 → 调 render_driver.py
render-draft --desktop --desktop-name &lt;desk&gt; 执行 → 完成后释放桌面。
设计要点：render_driver 每次自己 start + kill 剪映（用完即弃），桌面池只做互斥锁、
不常驻剪映实例，避免实例状态漂移，是吞吐量与隔离性的核心保障。

#### 二、业务对象

| 编码 | 业务对象 | 数据项 | 数据类型 | 长度 | 必填 | 编码引用说明 | 备注 |
|------|---------|--------|---------|------|------|------------|------|
| BO-06-004 | 桌面池条目 | desktop_name | VARCHAR | 32 | Y | 固定 JYRender_0/JYRender_1 | 2 并行 |
| | | busy | 布尔 | 1 | Y | true=占用 | 启动时初始化，不预启剪映 |
| BO-06-003 | 渲染队列元素 | task_id | VARCHAR(Hex) | 8 | Y | BO-06-001 | FIFO |
| | | enqueued_at | BIGINT | 毫秒 | Y | 入队时间 | queue.Queue 阻塞队列 |

#### 三、业务活动

初始化桌面池 → worker 循环阻塞取任务 → acquire_desktop(timeout=600) 阻塞等空闲桌面
（DESKTOP_LOCK 防竞争）→ 以该桌面名调 render-draft 子进程 → 回写任务状态 →
释放桌面 → 继续取下一任务。

#### 四、用例描述

##### 用例 U-06-004-01 双桌面并行渲染调度

| 项目 | 内容 |
|------|------|
| 用例编号 | U-06-004-01 |
| 用例名称 | 双桌面互斥并行渲染 |
| 业务说明 | 两个任务同时排队，池内两桌面各自渲染互不干扰，第三任务阻塞等待空闲桌面 |
| 规范引用 | 无 |
| 业务规则 | 1. 同一桌面同一时刻仅允许一个渲染任务占用（busy 互斥）；2. acquire_desktop 阻塞等待上限 600 秒，超时任务置 error；3. 桌面申请/释放全程持 DESKTOP_LOCK，防多 worker 竞争；4. 每次渲染 render_driver 自行启动并在结束时 kill 仅自己启动的剪映 PID（用完即弃，不常驻实例、不误杀其他桌面剪映）；5. worker 为 daemon 线程，随服务启停。 |
| 使用范围 | R04 系统运维/开发者（池行为监控）；上游 R01/R02/R03 任务提交方受益 |
| 先决条件 | render_server 启动时 desktop_pool 已初始化；Windows 会话具备创建桌面权限 |

**功能要求：**

| 类型 | 描述 |
|------|------|
| 基本功能 | 共计 5 个基本功能点：|
| | 1. 桌面池初始化（JYRender_0/JYRender_1，不预启剪映） |
| | 2. RENDER_QUEUE 阻塞队列任务分发 |
| | 3. acquire_desktop(timeout=600) 互斥桌面申请 |
| | 4. 以 --desktop --desktop-name 参数调 render-draft 子进程 |
| | 5. 渲染结束释放桌面（busy=false） |
| 辅助功能 | 多 worker daemon 线程并发消费 |
| 提示信息 | 桌面等待超时时任务 error 并说明原因 |

**处理逻辑：**
1. worker 从 RENDER_QUEUE 阻塞取 task_id；
2. acquire_desktop 在 DESKTOP_LOCK 内轮询空闲桌面，600s 未得则任务失败；
3. 置任务 rendering，启动 render_driver.py render-draft &lt;draft_fold&gt; --desktop --desktop-name &lt;desk&gt; --close，子进程退出后回写 done/error，释放桌面。

**约束条件：**
1. 桌面池容量固定 2，扩容需同步调整 DESKTOP_NAMES 并重新校准坐标；
2. kill 剪映仅限本任务自己启动的 PID，禁止按进程名全局查杀；
3. 桌面名全局唯一，供 calib 坐标与日志关联。

### S06-005 渲染状态/下载/列表 API

#### 一、功能综述

面向人机两类调用方提供渲染结果观测面：/render/status/&lt;task_id&gt; 单任务状态查询、
/render/download/&lt;task_id&gt; 成片下载（仅 done 后）、/render/list 全量任务列表。
Web GUI 渲染面板（S07-007）轮询展示进度；MCP render_status（S08-003）与对话工具
（S04-004）据此回答"渲染好了吗"；脚本流水线据此决策下载时机。

#### 二、业务对象

引用 BO-06-001 渲染任务（13 字段全量字典见 S06-003）与 BO-06-005 渲染产物，
本功能不新增数据项，仅提供只读查询与文件流输出。

#### 三、业务活动

单任务状态查询（按 task_id 读 tasks 字典）→ 任务列表查询（遍历全量）→
成片下载（校验 done 后以文件流返回 mp4）。

#### 四、用例描述

##### 用例 U-06-005-01 渲染状态查询与成片下载

| 项目 | 内容 |
|------|------|
| 用例编号 | U-06-005-01 |
| 用例名称 | 轮询状态并下载成片 |
| 业务说明 | 调用方轮询 /render/status 直至 done，再经 /render/download 拉取 mp4 |
| 规范引用 | 无 |
| 业务规则 | 1. status 返回状态枚举（queued/rendering/done/error），done 附带 mp4_name/duration，error 附带原因；2. download 仅对 done 任务有效，非 done 任务返回错误响应；3. /render/list 返回全部任务；4. 查询为只读操作，不改变任务状态机；5. 下载以二进制流返回 mp4，文件名取 mp4_name。 |
| 使用范围 | R01 视频创作者、R02 外部 AI Agent、R03 脚本/程序调用方 |
| 先决条件 | task_id 存在（由 S06-001/S06-002 返回） |

**功能要求：**

| 类型 | 描述 |
|------|------|
| 基本功能 | 共计 3 个基本功能点：|
| | 1. GET /render/status/&lt;task_id&gt; 状态查询 |
| | 2. GET /render/download/&lt;task_id&gt; 成片下载（done 限定） |
| | 3. GET /render/list 任务列表 |
| 辅助功能 | error 任务透出失败原因文本 |
| 提示信息 | task_id 不存在 / 任务未 done 时返回提示 |

**处理逻辑：**
1. 按 task_id 查 tasks 字典（加锁读），status 端点组装状态 + 产物信息 JSON；
2. download 端点校验 done 后返回 mp4 文件流；
3. list 端点遍历任务字典汇总返回。

**约束条件：**
1. 查询端点不得阻塞渲染 worker（快照读）；
2. 下载依赖 Videos 输出目录产物仍存在（S06-010 仅清草稿不清产物）；
